# お出かけマップ（ヨシトモの二人旅ログ）ver.2

元のアプリを維持し、次の4つを修正しました。

1. Googleマップ共有URL：通常のURLはブラウザで解析。`maps.app.goo.gl` などの短縮URLは、同梱した `api/resolve-map.js` をVercelに配置すると自動展開できます。
2. 2人の自動同期：Firebase Authentication（匿名ログイン）＋ Cloud Firestoreのリアルタイム更新。共有コードまたはURLを2人で使います。
3. 編集：一覧・地図のペンアイコンから、既存データの各項目を編集できます。
4. 都道府県：地図タップ・座標・Googleマップからの読み込み時に逆ジオコーディングで自動判定。名前検索でも判定します。判定できない場合は手動選択できます。過去の未判定スポットは「都道府県の制覇度」タブの「都道府県が未設定のスポットを自動判定」から一括補完できます。

JSON読み込みは従来の「全置き換え」から**IDを基準とした追加マージ**に変更。元のスポットは維持されます。クラウド接続時も、元の端末の記録を初回1回だけ合流させます。

## ファイル

- `index.html` : メイン画面
- `app.js` : 登録、編集、位置検索、Firebase同期などのコード
- `api/resolve-map.js` : Googleマップ短縮URL解決用のVercel API
- `firestore.rules` : Firestoreに設定するセキュリティルール

## 1. まずローカルで確認する

`index.html` をブラウザで開くと、以前と同じように**ローカル保存モード**で記録できます。編集・都道府県判定・通常のGoogleマップURL取り込みも利用できます。地図表示や施設検索にはインターネット接続が必要です。

ただし `file://` では短縮URL解決APIは実行できません。次の手順でVercelへ公開してください。

## 2. Vercelに配置する

GitHubリポジトリに `index.html`、`app.js`、`api/resolve-map.js` を、上記のディレクトリ構成でアップロードし、Vercelへインポートします。フレームワークプリセットは「Other」でよく、通常はビルドコマンド不要です。

公開URL例: `https://example.vercel.app/`。

※ **短縮URL展開はVercelのサーバーレスAPIが必要**です。単にHTMLファイルだけを開いても動きません。GoogleがURL形式や転送仕様を変更した場合、追加改修が必要な場合があります。

## 3. Firebaseを準備する（2人のリアルタイム同期用）

1. [Firebase Console](https://console.firebase.google.com/) でプロジェクトを作成。
2. 「Authentication」→「Sign-in method」→ **匿名（Anonymous）** を有効化。
3. 「Firestore Database」でデータベースを作成。**テストモードのままにしない**こと。
4. Firestoreの「ルール」タブで、同梱の `firestore.rules` をコピーして **公開（Publish）**。
5. 「プロジェクトの設定」→「マイアプリ」→ **ウェブアプリ** を登録し、表示された `firebaseConfig` の `{ ... }` 部分（または `const firebaseConfig = ...` のコード全体）をコピー。
6. アプリの「共有・設定」→「Firebase Webアプリの設定JSON」に貼り付け「Firebase設定を保存」を押す。
7. 「新しいルームを作る」→「共有リンクをコピー」→ 相手に送る。
8. 2人目も **同じFirebase設定JSON** を自分の端末で最初に1回貼り付け、共有リンクを開く（またはルームコードを入力して接続）。

> 別の端末でFirebase設定JSONを入力しなくてよいようにするには、`app.js` 冒頭付近の `EMBEDDED_FIREBASE_CONFIG = null` をコピーしたJSONオブジェクトに置き換えてVercelに再配置します。FirebaseのWeb設定はクライアントで使う公開識別情報であり、サービスアカウント秘密鍵ではありません。**Firebaseの秘密鍵は絶対に貼り付けないでください。**

### 共有とプライバシーに関する注意

- 共有ルームは192ビットのランダムコードを持つ「秘密のURL」方式です。コードを知る人は、匿名ログインでそのルームを閲覧・編集できます。**厳密にユーザー2人だけを認証する仕組みではありません。** 共有リンクの扱いに注意してください。
- Firebase側で指定のセキュリティルールを設定しないと、同期は拒否されます。誰でも全データへアクセスできる開放ルール (`allow read, write: if true`) は使用しないでください。
- Firebase設定JSONは端末のlocalStorageに保存。ルームコードはURLの `#room=...` にも含まれます。URLを不特定多数に公開しないでください。
- Firebase無料枠には利用量制限があります。大規模な利用には適切な監視・料金管理が必要です。

## データの安全性

- 以前のデータキー `pair_map_places` は削除・上書きせず、そのまま保持します。
- クラウド同期で追加・変更・削除した内容はクラウドの個別スポットに反映され、別のユーザーの異なるスポットを置き換えません。
- オフラインで編集した内容は端末内の同期待ち一覧に残し、再接続すると再送します（ブラウザが端末データを消した場合は復旧できません）。
- JSONバックアップはこまめに取得してください。意図しない削除は同期で全端末に反映されます。完全な変更履歴・復元機能は未実装です。
- **同一スポットを2人で同時編集すると後から同期された変更が優先**されます。

## 検証するポイント

1. 既存の保存データを消さずに、スポットが表示されること。
2. 一覧の編集アイコンから名前・評価・色・都道府県などを変更できること。
3. `maps.app.goo.gl` のURLがVercel環境で読み込めること。
4. 地図をタップし、都道府県が自動設定されること（Nominatimの通信が必要）。
5. 別ブラウザ・別端末で同じ共有ルームに入り、追加・編集・削除が同期されること。
6. JSON読み込みで既存データが消えないこと。

## 依存サービスと利用条件

- 地図: [国土地理院](https://maps.gsi.go.jp/development/ichiran.html) / [Leaflet](https://leafletjs.com/)
- 位置検索・都道府県判定: [Nominatim / OpenStreetMap](https://operations.osmfoundation.org/policies/nominatim/) （最大毎秒1件のアクセス間隔、利用制限あり）
- 同期: [Firebase](https://firebase.google.com/docs/firestore) （認証・Firestore・セキュリティルールの設定が必要）
- 短縮URL: Googleマップ公開共有URLのHTTP転送先を取得。Google公式の位置情報APIを使用するものではなく、将来のURL変更により取り込めない場合があります。
